Engineering Standards & Best Practices

Last Updated: 2026-04-16
Status: Canonical

🛡️ Core Principles (The HisabKit Way)

  1. Modular Monolith: Strong internal module boundaries within a single deployable unit.
  2. Vertical Slices: Organize code by business feature (ledger, identity, settings) rather than technical layer (service, repository).
  3. Thin Controllers: Controllers are for routing and validation ONLY. Business logic resides in the Service layer.
  4. DTO Safeguards: Use dedicated Request/Response objects for all API boundaries. Never leak JPA entities or Prisma models to the client.
  5. Explain “Why”, Not “What”: Code comments should explain intent and invariants, not restate the obvious.

🏗️ Architectural Standards

1. Vertical Slice Architecture

  • All code related to a specific business domain MUST live together.
  • Backend (Spring Boot): com.nayag.hisabkit.modules.<module-name>
  • Frontend (Web/Mobile): src/modules/<module-name>

2. Module Boundaries

  • Modules may only interact through public service interfaces or shared models.
  • Avoid circular dependencies between modules.
  • Shared logic that spans multiple modules MUST be extracted to src/shared (Web) or packages/features (Monorepo).

3. Thin Layering

  • Controller/Router: Http mapping, input validation, and delegation.
  • Service: Business logic, transactional boundaries, and multi-module orchestration.
  • Repository/Access: Database interactions only.

🎨 Frontend Standards (React/Native)

1. UI Consistency

  • ALWAYS prefer shared primitives from src/components/ui (Web) or packages/ui over ad-hoc Tailwind markup.
  • All new UI work must support Dark/Light/System themes via HSL variables.

2. Component Design

  • Atomic Thinking: Breakdown large views into functional components.
  • No Mega-Files: Files exceeding 300 lines should be decomposed.
  • Lazy Loading: Use React.lazy for all top-level route components to optimize bundle size.

3. State Management

  • Server State: Use TanStack Query (React Query) for all API data.
  • Local State: Use useState or useReducer for UI-only state.

⚙️ Backend Standards (Spring Boot)

1. REST API

  • Use Conventional HTTP Methods (GET, POST, PUT, PATCH, DELETE).
  • Return standard Status Codes (200, 201, 400, 401, 403, 404, 500).
  • Use ResponseEntity for all controller returns.

2. Security & Multi-Tenancy

  • Authentication: JWT-based stateless tokens.
  • Multi-Tenancy: Every request must be validated against the X-TenantID header.
  • Permissions: Check feature-flag or role access at the Service level.

3. Data Integrity

  • Use Liquibase for all schema changes.
  • Ensure all business transactions are marked @Transactional.

🧪 Testing Standards

  • Unit: All complex business logic must have 80%+ coverage (JUnit 5 / Vitest).
  • Integration: Critical API endpoints must be tested with @SpringBootTest (Backend) or Playwright (Web).
  • E2E: Critical “Golden Paths” (e.g., creating a ledger) must be automated.

🛡️ Quality Gates

Before merging, every Pull Request MUST:

  1. Pass Biome linting and formatting (npm run lint).
  2. Pass TypeScript type checking (npm run typecheck).
  3. Pass all Unit Tests (npm run test).
  4. Successfully Build (npm run build).

🧑‍💻 Agentic Workspace Rules

For AI Agents (Cursor/Claude):

  • Always audit agents/rules/ before proposing structural changes.
  • Follow the .cursorrules located at the root for project-specific guidance.
